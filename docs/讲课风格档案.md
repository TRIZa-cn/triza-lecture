# 讲课风格档案 · 刘文印

> 来源：本仓第 1–16 讲的历次修改、提问与返工记录。每一条都对应真实发生过的修改，不是凭印象写的。
> 版本：v1.0（2026-11-01）。更新方式见文末。

## 一、语气与人称

1. **第二人称直呼「你」**。讲台上是「你现在打开 TRIZa」，不是「我们会打开」。第一人称只用于示弱和自嘲（「我第一次画功能图也画歪了」）。
2. **口语连接词必须密**。每 100 字至少 3 个：所以、但是、因为、比如、说白了、其实。书面腔一旦出现，学生会走神。
3. **不许端着**。「综上所述」「由此可见」一律改成「所以说」「你看」。

## 二、结构

4. **先给困境，再给定义**。每一讲的开头三句是三个具体场景（翻开表、套不上、别人用得很妙），第四句才说「共同点是……」。不先讲定义。
5. **一页一个论点**，标题是判断句不是名词短语。「知道有四十条，问题还是想不出办法」好过「发明原理概述」。
6. **结尾固定三句话 + 下次预告**。三句话是能带走的，不是总结全文的。
7. **每讲留一个钩子**，最后一页必须说清下一讲解决什么，并说明「用的就是这个方案」。

## 三、举例

8. **例子必须跨行业**，一讲里至少三个不同领域（制造、医疗、软件、物流、农业）。
9. **数字要给量级**，不说「响应变快」，说「改前平均八百毫秒、峰值两秒，改后预期平均两百毫秒」。
10. **例子标明是教学示例**，不编造实验结果，不说「某企业实测提升 37%」。

## 四、可执行性

11. **每个概念都要落到「动的是哪个对象」**。说不清动谁，就是没落地。
12. **一次只验证一条**。禁止「五条原理一起上」的大杂烩，否则说不清因果。
13. **练习必有交付物**：三样东西 + 改前改后各一个数 + 上传 TRIZa。

## 五、视觉

14. **正文 20pt 是底线**，宁可删内容也不缩字号。只有 kicker 14pt、页脚/页码/封面署名 12pt 可以小。
15. **一页不超过 6 条**，每条不超过两行。
16. **例图优先于文字**。能画图的地方不要写三段话（见 SKILL 例图规范）。

## 六、反面清单（出现过就必须改）

- 封面写「五条」正文写「六条」——条数必须全篇唯一。
- 表格只有五行，但框里列了六条——表和框必须同源。
- 把原理名当答案：「采用分割原理」等于没说。
- 一页塞三段并列内容，学生不知道先看哪。
- 讲稿写成论文摘要，没有「你」。

## 七、怎么更新

每发生一次修改，问三个问题：

1. 这次改的是**词**、**结构**、还是**取舍**？
2. 能不能写成一条可检查的规则（有触发条件、有判断标准）？
3. 有没有反例？反例写进反面清单。

满足三条才写进本文件，并同步更新 `style/style_profile.json` 与 SKILL 对应章节。只写「更生动一点」这种不可检查的话，等于没写。
