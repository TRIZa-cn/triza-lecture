# 风格包如何接入 akbank 与 ideation

## 1. 一句话

把「刘老师的讲课风格」从散落在对话里的隐性偏好，变成一个**带版本、可校验、可被创新构思流程选用**的资产包。

## 2. 风格包的三个组成部分

| 组成 | 文件 | 作用 |
| --- | --- | --- |
| 规则 | `style/style_profile.json` | 机器可读，14 条，每条带 check |
| 说明 | `docs/讲课风格档案.md` | 人读，讲清为什么这么定 |
| 校验器 | `PPT/W2_16/w_style.py`（待建） | 读 pptx，逐条打分，输出 JSON |

规则必须**可检查**。写「更生动」不算规则；写「每 100 字 ≥3 个口语连接词」才算。

## 3. akbank 侧：风格作为一类资产

akbank 现在存的是「知识点/案例」。建议新增一类 **style-pack**：

```json
{
  "type": "style-pack",
  "id": "lwy-lecture-style",
  "version": "1.0",
  "owner": "刘文印",
  "scope": "lecture-writing",
  "payload": { "rules_ref": "style/style_profile.json" },
  "rubric": [
    {"rule_id": "R01", "weight": 1.0, "hard": true},
    {"rule_id": "R12", "weight": 2.0, "hard": true}
  ],
  "provenance": [
    {"kind": "edit", "ref": "deck: 第4次课补齐反向作用", "date": "2026-11-01"},
    {"kind": "question", "ref": "用户提问：第4周是五条还是六条", "date": "2026-11-01"}
  ]
}
```

要点：

- **provenance 必须真实**。每条规则背后要有一次真实修改或一次真实提问，否则不进 akbank。
- **hard / soft 分开**。R12（条数自洽）、R14（不编数据）是 hard，违反即拒绝；R06（三个跨行业例子）是 soft，扣分不拒绝。
- **版本绑定**。风格包升级不覆盖旧版，创新构思时可选「用 v1.0 风格」还是「用最新」。

## 4. ideation 侧：构思时可选风格

创新构思的入口多一个下拉框：

```
输出风格：  [ 默认（中性）  ▾ ]
            默认（中性）
            刘文印 · TRIZ 讲课风格 v1.0
            刘文印 · 专利撰写风格 v0.9
```

选中后发生三件事：

1. **注入**：把 style_profile 的 tone/structure/examples 段落作为系统提示的约束片段，附 2–3 段真实讲稿作为 few-shot。
2. **约束**：把 hard 规则变成生成时的硬约束（例如「一次只验证一条」「不编数据」）。
3. **自检**：生成后跑校验器，返回 rubric 得分与违规条目，用户看得见。

关键设计：**风格不改变事实**。风格包只影响措辞、结构、举例密度，不允许影响结论、数据与判断。所以 ideation 里风格是「表达层」参数，不是「推理层」参数。

## 5. 数据流

```
每次修改课件 / 每次提问
        │
        ▼
  人工确认：这条能不能写成可检查规则？
        │  能
        ▼
  style_profile.json 升版本 ──► akbank style-pack ──► ideation 风格选择器
        │                                              │
        └──────────► SKILL.md 对应章节 ◄────────────────┘
```

**不能自动写入**。风格提取必须经过一次人工确认，否则模型会把一次笔误当成风格。这是本设计最重要的一条。

## 6. 落地顺序（建议）

1. 本轮：规则文件 + 说明文档（已具备）。
2. 下一步：写 `w_style.py`，把 14 条规则里可自动检查的 8 条实现（R01/R02/R05/R10/R11/R12/R13/R14）。
3. 再下一步：akbank 加 style-pack 类型，先只在内部用。
4. 最后：ideation 加风格下拉框，默认关闭。

## 7. 风险

- **风格过拟合**：规则太多会写出千篇一律的稿子。规则控制在 15 条以内，且允许 20% 偏离。
- **rubric 变成刷分**：风格分高不等于讲得好。风格分只做提示，不做验收门槛。
- **隐私**：风格包属于个人资产，只在该教师授权的项目里可见，不随仓库公开分发。
