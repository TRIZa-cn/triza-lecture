# triza-lecture

把一节课从**设计**做到**可播放的演播版**的流水线。

这个目录是插件骨架，目前只放方法与约定，不放具体讲义内容。
讲义源码、讲稿、生成脚本留在作者本地工作盘，不随本仓发布（见 `README.md` 的白名单说明）。

## 它解决什么问题

做一节课会反复踩同样的坑：

1. 讲稿写得挺顺，但**结构缺段**——收场没有可执行动作，学生听完就散了；
2. 图没画，或者画了但对不上讲稿——图上有的词，讲稿里没讲；
3. 录音要一遍遍重来，改一句稿就重录整段；
4. 录完发现动画和旁白对不上——观众不知道该看哪里；
5. 做完没人验收，只有"感觉还不错"。

这条流水线给每个环节一个**可检查的出口**，而不是靠感觉。

## 五段流水线

| 段 | 输入 | 产出 | 门禁（不过就不许往下走） |
|---|---|---|---|
| 1 设计 | 一个能一句话说清的钉子 | 七段结构表 + 验收标准 | 收场有"绝招"且≠"回去想想"；验收标准可观察 |
| 2 讲稿 | 结构表 | 逐字稿 + 导演指令（分两段） | 每页只讲一个点；术语首次出现有白话 |
| 3 排版 | 讲稿 | `.pptx`（原生形状，非位图） | 字号下限、溢出检查、页脚页码 |
| 4 配音 | 定稿讲稿 | 逐页音频 | 只用允许的声音源；不串页、不丢句 |
| 5 合成 | 音频 + 版式 | 演播版（自动翻页 + 定时动画） | 每页有音频、能自动播、动画与台词对齐 |

设计段与验收标准为什么分开：**七段管"抓不抓得住"，验收管"学没学会"**。
前者来自商业课方法论，后者要用逆向设计补，两者不能互相替代。
