cover :: 这次讲发明原理。前两讲我们画了功能图、挖了因果链，知道哪里不足、为什么不足。但知道问题在哪，不等于知道怎么改。发明原理就是改的套路库。今天不讲四十条，只讲六条，因为四十条里真正高频的就那十来条，你把六条用熟，比背四十条有用得多。
dilemma :: 三个场景。翻开原理表，四十条看一遍，每条都像，每条都用不上。硬套一条，方案写出来自己都觉得别扭。同一条原理别人用得很妙，你用就成了常识。共同点是把原理当答案找。其实它是改动的方向，方向本身不解决问题，方向落到具体对象上才解决问题。
define :: 定义：从大量专利里归纳出来的改动套路。它不告诉你做什么产品，只告诉你往哪个方向动一下。四十条里高频的只有十来条，先学这十来条。同一条原理在不同领域表现完全不同，这正是它的价值。判据框那句最要紧：原理必须落到具体动作，分割什么、抽取什么、预先做什么。说不清动的是哪个对象，就是没落地。
why :: 为什么值得学？第一，换视角。同一个矛盾，分割能解，反向也能解，成本差十倍。第二，可比较。几条原理各出一个方案，你才有得选。第三，可解释。为什么这么改能说清依据，写论文时审稿人会问这个。说白了，原理不是灵感替代品，是让方案数量从一变成五的工具。
flow :: 四步。先定对象，这次要动的组件或参数，一句话写清。再选原理，从高频的十来条里挑两三条。然后翻译，问在我的场景里被分割的是什么、被抽取的是什么，这一步是全部功夫所在。最后验算，写出改完的预期指标，能测才算方案。高频六条我列在框里：分割、抽取、局部质量、预先作用、反向作用、中介物。
table :: 这张表是速查。分割是拆成可独立处理的部分，落到你场景里就是分块训练、分段评估。抽取是只保留有用的那部分，比如只测有用频段。局部质量是不同位置给不同待遇，比如难样本加权。预先作用是把该做的提前做完。中介物是加一个中间载体来传递。记住一句话：挑一条，不要挑六条。
ex2 :: 预先作用。你以为是算法快，其实是结果早就算好了。缓存、预热、预取，本质都是把时间挪到用户不等待的时候，代价是内存和一致性，必须写清楚。怎么验算？改前平均响应八百毫秒、峰值两秒，改后预期平均两百毫秒、峰值不变。如果峰值也降了，说明你改的不是这一条。
warn :: 三个把原理用废的方式。把原理名当答案，写采用分割原理，等于什么都没说。一次用五条，方案变好也说不清是哪条起的作用。不做验算，没有预期指标，方案就无法被推翻。自检问题：你的方案里哪一句能直接对应到原理的动词？对不上，就是贴标签。
prompt :: 在 TRIZa 里怎么用。第一句带上你的矛盾句，来自第 1 次课。第二句要求只用一条原理，给三个跨行业实例。第三句要求针对你的场景写出具体改动，动的是哪个对象、怎么动。第四句要预期指标和验证方式。第五句是护栏，禁止混合方案。护栏很重要，模型特别爱给你五条原理的大杂烩。
task :: 练习十二分钟。从六条里挑一条，写下为什么挑它。找三个不同行业的应用，各一句，注明行业。抽象出共同动作，一句话。移植到你的课题，写出改动和预期指标。提交三样：原理加例子加方案、改前改后各一个数、上传 TRIZa。第 5 次课做物场模型，用的就是这个方案。
summary :: 三句话。原理给方向不给答案，方向要落到一个具体对象上。一次只验证一条，否则说不清是谁起的作用。三个跨行业例子是门槛，找不出三个，说明你的抽象层级不对。下次讲物场模型与标准解，功能不足或有害时，怎么系统地补一个场进去。
