# 英文缩写读音规范

和 `polyphone.md`（中文多音字）共用同一个替换器 `apply_polyphone.py`，同一张逻辑：
**页面文字不动，只在"喂给 TTS 的那一份文本"里换成读音确定的形式。**

---

## 1. 英文缩写比中文多音字更难，因为它有三种读法

中文多音字是"两个音选一个"。英文缩写是 TTS 自己会在三条路里挑，而且你不知道它挑哪条：

| 读法 | 例子 | 什么时候会被选中 |
|---|---|---|
| **逐字母** | W-A-F、P-零-六 | 全大写、没有元音组合时最常见 |
| **拼读成词** | WAF 读 /wæf/、TRIZ 读 /triːz/ | 能拼成一个音节时 |
| **中文音译** | TRIZ 读"特瑞兹" | 中文模型对不认识的英文串兜底时 |

同一个词，换一版模型、换一句上下文，读法就可能变。**所以不能只写一句"读 XX"，必须指定合成文本。**

---

## 2. 处理档位：两档，不含中文音译

**中文音译不用。** 作者明确否决「特瑞兹」「吹兹」「萃智」这类译法——它们把英文术语的听感换掉了。
所以只剩两条路：

### 第一档 · 改写成中文说法（最稳，优先）

把缩写换成中文，等于绕开这个问题：

| 原文 | 改后 | 为什么 |
|---|---|---|
| 翻回 P06 | 翻回第 6 页 | 中文讲稿里本来就这么说，TTS 无歧义 |
| 那是 P12 | 那是第 12 页 | 同上 |
| 配图见交接文档 F1 | 配图见交接文档第一张 | 同上 |

代价：改的是讲稿文字。但这一档收益最大——**页码标记是本片出现最多的英文串（13 处）**，
而且"P零六"这种读法在课堂里很刺耳。

### 第二档 · 英文 respelling（默认走这档）

用同音英文词拼出目标读音，**这是 TRIZ / TRIZa 采用的档位**：

| 缩写 | respelling | 目标音 |
|---|---|---|
| TRIZ | trees | /triːz/（treez，末尾是浊 z） |
| TRIZa | treeza | /ˈtriːzə/ |
| WAF | W-A-F 或 waff | /wæf/ |

**这一档必须在实际模型上试听。** 中文声音模型读 `trees` 可能读成生硬的 /triːs/（清音 s）。
本机没有验证过——**不要假设它一定对**。

> 实测补充（V3 已落地的做法，来自 GPU 机器的交接文档）：那套 TTS 没有音素接口，
> 最终采用的是「汉字逼近」——`tree字`（/triː tsɯ/）、`吹咋`、`哇夫`。
> 这不是"音译"，是**用汉字拼出英文音**，与本节第二档目的相同（保英文听感）。
> 三档变体的取舍以试听为准，本表只规定"不用中文译名"。

## 3. 本片（W2）必须处理的，只有 5 类

统计口径：只算 `notes`（会被念出来）。页面上的 `P09 ·` 这类是排版标记，不进配音。

| # | 缩写 | notes 出现 | 页 | 建议 | 依据 |
|---|---|---|---|---|---|
| 1 | **TRIZ** | 3 | 全片 | trees（或 `tree字`） | 用户指定读 treez |
| 2 | **TRIZa** | 4 | 13 | treeza（或 `吹咋`） | 用户指定读 treeza |
| 3 | **WAF** | 3 | 7、12 | 待作者定 | 见下 |
| 4 | **页码 P03/P06/P07/P08/P12/P13/P15** | 13 | 多页 | **改写成"第 N 页"** | 见第 2 节第一档 |
| 5 | **F1** | 1 | 8 | 第一张 | "配图见交接文档 F1" |

**注意区分 TRIZ 与 TRIZa。** 讲稿里 `TRIZ`（方法论）与 `TRIZa`（产品）都出现，
读音不同（/triːz/ vs /ˈtriːzə/），不能用同一条替换规则——会互相覆盖。

WAF 的三种可能：`W-A-F`（逐字母，最保险）、`waff`（/wæf/，行业里有人说）、
"网页应用防火墙"（讲稿 P12 已经解释过一次）。**这一条我没有依据说哪个对，留给作者定。**

## 4. 通用术语表（TRIZ 教学常用）

只收会念到的。**"状态"列：确认 = 作者说过的；待确认 = 我的建议，需作者拍板。**

| 缩写 | 全称 | 目标读音 | respelling | 状态 |
|---|---|---|---|---|
| TRIZ | Теория решения изобретательских задач | /triːz/ | trees | **确认** |
| TRIZa | （产品名） | /ˈtriːzə/ | treeza | **确认** |
| ARIZ | Алгоритм решения изобретательских задач | /ˈɑːrɪz/ | ah-riz | 待确认 |
| IFR | Ideal Final Result | 逐字母 | I-F-R | 待确认 |
| FMEA | Failure Mode and Effects Analysis | 逐字母 | F-M-E-A | 待确认 |
| RCA | Root Cause Analysis | 逐字母 | R-C-A | 待确认 |
| QFD | Quality Function Deployment | 逐字母 | Q-F-D | 待确认 |
| TOC | Theory of Constraints | 逐字母 | T-O-C | 待确认 |
| SIT | Systematic Inventive Thinking | 逐字母 | S-I-T | 待确认 |
| WAF | Web Application Firewall | 待定 | W-A-F / waff | 待确认 |
| API | Application Programming Interface | 逐字母 | A-P-I | 待确认 |
| LLM | Large Language Model | 逐字母 | L-L-M | 待确认 |

**规律**：能读成一个词的（TRIZ、ARIZ）走拼读；不能的就逐字母。**没有一条是"看情况"。**

---

## 5. 怎么验证（不能省）

1. **先跑替换器**，看 `missed` 是否为空（讲稿改过就匹配不到）。
2. **抽 3 句试听**：一句 TRIZ、一句 TRIZa、一句页码改写后的。
3. 试听标准只有一条：**听众第一遍能不能听出是哪个词**。听不懂就是没成功，换档。

本机未验证的部分要明说：

- 中文本人声音模型读 `trees` / `treeza` 的实际效果：**未测**。
- 改用 `tree字` / `吹咋` 的效果：GPU 机器已试听确认（见 V3 交接文档第 4 节），本机未复核。

---

## 6. 一句话

中文多音字靠"同音字替换"，英文缩写靠"改写或 respelling 二选一"。
**中文译名不用**；能改写成中文的，永远最稳；改不了的，才去赌 TTS 的英文发音。
